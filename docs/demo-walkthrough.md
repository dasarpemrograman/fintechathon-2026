# Offline demonstration

Start with `APP_MODE=demo .venv/bin/python scripts/seed_demo.py`, then `.venv/bin/python scripts/dev.py start --demo`. The development launcher also seeds before starting the worker. Open http://127.0.0.1:3000 and choose a displayed demo identity. No default password is committed. There are owner, export admin, finance reviewer and production/procurement identities for the isolated ID, CN and KE organizations. Cross-organization resource IDs grant no access.

The base dataset has ten entry workspaces: producer/reseller × sandbox/deal across ID/CN plus generalized KE→DE and a CN→AE multi-line, multi-shipment fixture. All values and source documents are synthetic. The business reference date is 2026-10-16. Base cases preserve their independent calculation goldens; sandbox cases use the same calculator and explicit hypothetical input model.

Four additional coffee checkpoints retain causal command histories. `negotiation` preserves the original funding-gap analysis, changes both deposit and balance, recalculates and prepares an unsent draft. `blocked_goods` has a larger deposit, reviewed requirements, opening-bank evidence and a verified buyer advance, but nonconforming goods. `reconciling` records full buyer payment while seller liabilities and final actual charges remain open. `closed` records reviewed actual costs, each settlement, measured goods conformity, separate owner/counterparty reviews, evidence of delivery and a successful current reconciliation/closure gate. Checkpoints start on 2026-08-01 so their synthetic actuals precede the fixed reference date.

For a blocked journey, enter as ID owner, open `Synthetic coffee · blocked goods`, then Kesiapan & jadwal. Inspect the goods-conformity blocker and evidence. Full buyer payment on another case does not remove this blocker. For a completed journey, open `Synthetic coffee · closed`, compare historical analyses, inspect original sources, the final reconciliation and the independent buyer-payment/internal-closure dimensions. Draft downloads remain drafts and contain legal placeholders.

For an interactive calculation, open the base Coffee Transaksi card, inspect Biaya & arus kas, then Ringkasan → Hitung ulang analisis. The API accepts a durable job; the separate worker writes the result and the browser polls it. Reload retains database state. Source-review commands, draft preparation and hypothetical financing comparisons use the same services as the seed. No browser response interception or outgoing trade actions are involved.

`seed_demo.py` resumes checkpoint phases from audit evidence and does not overwrite user edits once a phase is complete. Rerunning it creates no duplicate completed fixtures. `APP_MODE=demo .venv/bin/python scripts/reset_demo.py --dataset demo-v1` performs a preflight. Add `--apply` for an explicit namespace reset. It scans retained records, immutable history and references; mixed ownership blocks deletion. Database volumes, unrelated user data and content-addressed files remain. Shared files are retained conservatively; this command is not global garbage collection.

The current app and test evidence are recorded in the active OpenSpec tasks. Optional Calendar and live-provider acceptance have separate gates; an offline receipt never counts as live validation.

Under Biaya & arus kas, open **Telusuri rumus dan versi sumber** below the calculated metrics. Each formula links to its fixed source revisions. Expand **masukan versi tetap** to inspect the original costs, obligations and workspace/deal inputs, including native amounts and explicit unknowns. The source panel shows historical review status, source mode, expiry, locators and hashes. For document-backed evidence, **Unduh sumber asli** downloads the unchanged authorized original. Historical review never grants permission for a new action. The base Coffee Transaksi case has document-backed evidence; checkpoint excerpts may have no original-file download.

Owner reviews, counterparty acceptance and verified funds are separate records. Review the current analysis and evidence hashes before an owner approval, and bind draft review to its exact artifact hash. Record each required counterparty's acceptance against the currently reviewed revision with supporting evidence. An owner's plan review never counts as the buyer's agreement, an opening-bank verification or a verified advance. Existing acceptance histories remain usable only while their commercial terms and agreed milestone hashes still match. Changed evidence preserves the old artifact/review history and requires a fresh review before new action.

The optional Calendar panel under Kesiapan & jadwal offers a clearly marked offline connection. Select internal milestones, inspect the generic titles/dates and projection hash, approve that hash, then request the synthetic projection. No Google call occurs. Read the outbox status separately from job acceptance. Revocation disables further projection; a conflict preserves the external event until an owner chooses to retain it or review the projection again. Real Calendar acceptance requires a configured test account and is tracked separately.

To exercise an offline Calendar conflict, create a milestone first, connect the demo calendar, preview and approve its hash, then wait for `delivered` in the connection status. Run `APP_MODE=demo .venv/bin/python scripts/demo_calendar_conflict.py --connection <connection-id> --milestone <milestone-id>` against the same database (or use `compose ... exec -T api python scripts/demo_calendar_conflict.py ...`). This command changes only an existing synthetic projection of a seeded milestone. Refresh the panel to retain the external version or require another projection review. It never contacts Google. Revocation remains visible and prevents further writes.

Opening cash can be updated under Ringkasan → Batas dan preferensi pemilik. Supply available cash, outside commitments, minimum buffer, their currencies and the actual UTC snapshot time together. An empty value is not zero. A changed snapshot needs a new resource review; saving it never verifies bank funds. Payment adjustments are under Pembayaran & penutupan; quoted-cost entry is under Biaya & arus kas.

A namespace reset clears derived synthetic Calendar projections of the seeded milestones and preserves separately owned connections. A retained or live event dependency blocks reset for explicit review. Never use this reset to delete a real Calendar event or database volume.
